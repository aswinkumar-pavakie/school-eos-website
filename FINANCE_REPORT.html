Approvals engine

2
  • ✓
    One shared approval engine
    A single, generic routing engine sits under Concessions, Purchase/Service Requests, Refunds, Expenses, and Fee Structure activation — every decision is fully audited: who, when, and what they said.
  • ✓
    Role-scoped views
    Finance/Admin see the full module; the Principal gets a deliberately narrow view — only what's actually routed to them.

Built to this standard

  • No floating-point money. Every amount is stored and handled as integer paise.
  • Real state machines. Every status is a constrained value checked against the database, never assumed.
  • Full audit trail. Every sensitive action is logged with who, when, and why.
  • Enforced at the API. Role access is checked server-side on every request, not just hidden on screen.

The parent's own view of their child's fees, and a real, working online payment — inside the mobile app, not a redirect to a browser.

Viewing fees

5
  • ✓
    Multi-child support
    A parent with more than one child at the school switches between them; every screen reflects the one currently selected.
  • ✓
    Term selector
    Pick the academic year and instalment to view — defaults to the most recent real term.
  • ✓
    Total / Paid / Outstanding summary
    A live rollup for the selected term, computed from real fee-demand data, not cached or estimated.
  • ✓

    Every fee head shown with its own total, paid, and due amount, and a clear status pill (Pending / Partial / Overdue / Paid).

Paying online

5
  • ✓
    Select which fee lines to pay
    Checkbox-select one or more still-due lines; the amount owed updates to match the real selection.
  • ✓
    Partial payment
    A parent can type a smaller amount than the full due and pay that now, settling the rest in a later payment.
  • ✓
    Razorpay checkout, in-app
    A real hosted Razorpay order, opened directly inside the app — no browser hand-off.
  • ✓

    A payment is only ever marked confirmed by Razorpay's own webhook hitting the backend directly — the app closing the checkout screen never marks anything paid on its own.
  • ✓

    A guardian with view-only access (not the primary payer) sees everything but the Pay button is correctly disabled, with a clear reason shown.

Events & Permissions

04 / mobile app · faculty + parent

Digital consent for student event participation — a faculty member requests it, a real parent signs it, and it produces a professional, downloadable permission letter. Built across both the Faculty and Parent sides of the mobile app.

Faculty side

7
  • ✓
    Create an event
    Name, location, purpose, and a from/to date & time window, with a real staff member picked as the monitoring teacher (searched, never free-typed).
  • ✓
    Events list & detail
    Every event a faculty member has created, as cards, with full detail on tap.
  • ✓
    Add students — search & filter
    Case-insensitive search by name or roll number, plus class/section filter chips, to find and add exactly the right students.
  • ✓
    Live status per student
    Each added student shows Waiting for approval / Approved / Rejected, updating in real time as parents decide.
  • ✓
    Remove a student
    Full CRUD — with one deliberate exception: a student whose parent has already signed can't be removed (see Security, below).
  • ✓
    Delete an event
    Same protection extends to the whole event — it can't be deleted while it holds even one signed approval.
  • ✓
    Download the permission letter
    Once a student is approved, download the same professional PDF the parent gets, for the school's own records.

Parent side

5
  • ✓
    Permissions list
    Every request across every one of the parent's real, linked children, as cards with a clear status.
  • ✓
    Full request detail
    Complete event information — location, purpose, timing, and the supervising teacher — before deciding.
  • ✓
    Reject
    One tap, with confirmation — a final decision, clearly labelled once made.
  • ✓
    Sign as Guardian
    A real digital signature pad — draw with a finger, Reset if it's wrong, then Approve.
  • ✓
    Download the permission letter
    Once approved, the Reject/Sign buttons are replaced with a Download button — a professional letter (school letterhead, student details, the actual signature) as a real PDF.

The permission letter

1
  • ✓
    One professional template, real data throughout
    From (the student's real class teacher + school letterhead), To (the parent who actually signed), Subject, a reusable request paragraph built from the real event details, and the parent's actual signature — nothing on it is a placeholder.

Security — this is the most sensitive feature in the app

  • Real consent records are immutable. Once a parent signs, that student can never be removed and the event can never be deleted, by design.
  • Scoped strictly. A faculty member only ever manages events they created; a parent only ever acts on their own, real, linked children.
  • No double-decisions. If both parents open the same request, whoever decides first wins — the second is safely blocked, never overwritten.
  • Signature verified, not assumed. The uploaded file is checked to be a genuine image, not just trusted by name or label, before it's ever stored.
